# Проверка перед публичной публикацией

Дата: 22 ноября 2026. Проверены публикуемые исходники, документация и состав первой версии Git. Это ограниченный ручной аудит с поиском признаков секретов, а не гарантия отсутствия всех уязвимостей и не полный аудит SDK/ОС.

## SEC-001 — высокая: утечка частных данных через документы, устранено для публикации

Исходные рабочие материалы содержали адрес доставки, домашнюю топологию сети, имена SSH-доступа, локальные пути, USB serial/MAC и публичный ключ администратора. Это раскрывало сведения о владельце и инфраструктуре. Приватные ключи или рабочие API-токены в публикуемом наборе не обнаружены.

Публичные PROJECT.md, ORDER.md, ASSEMBLY.md и README дальномера обезличены. Исходные копии сохранены локально в игнорируемом `.tools/publication-backup/`. CONTEXT.md, вся директория infra/, marketplace clone и результаты сессий исключены. Истории основного проекта до подготовки не было; приватные версии не включаются в первый коммит.

## SEC-002 — высокая при включении затронутых функций: устаревший SDK, открыто

`firmware/mic-test/platformio.ini:2` и `firmware/range-test/platformio.ini:2` закрепляют espressif32 6.12.0; рабочая среда использовала ESP-IDF 5.5.0. У ветки есть последующие исправления безопасности. Например, [GHSA-ch63-jxm5-vmvf](https://github.com/espressif/esp-idf/security/advisories/GHSA-ch63-jxm5-vmvf) затрагивает v5.5–5.5.5; исправление v5.5.6. Для этого конкретного DNS-переполнения требуется CONFIG_LWIP_DNS_MAX_HOST_IP > 1 и использование затронутого пути DNS-кэша.

Текущие app_main не запускают Wi-Fi, Bluetooth, DNS, HTTP или сетевые команды. Поэтому достижимость указанной сетевой уязвимости текущими тестами не выявлена. Это не утверждение о безопасности всех компонентов SDK. Версия сохранена для воспроизводимости проверенного стенда; перед сетью/камерой/OTA нужно перейти на совместимую исправленную версию, сверить [официальные advisories](https://github.com/espressif/esp-idf/security/advisories) и заново испытать оборудование. Обновление и перепрошивка в эту публикацию не входят.

## SEC-003 — высокая в исходных зависимостях MCP: исключено из публикации

Локальный сторонний Ozon MCP ранее имел 9 находок npm audit, включая critical. Историческая проверка производного образа не покрывает нынешние npm/Python/ОС-пакеты. Весь clone и Dockerfile с обновлениями @latest исключены. Публикуется только описание использованного инструмента и результатов; готовый безопасный MCP-дистрибутив не заявляется.

## SEC-004 — средняя: локальный UART не аутентифицирован, ограничение стенда

`firmware/mic-test/src/main.c:165` принимает команды от любого подключённого UART-клиента; `capture.py` записывает голос на диск. Передача ограничена фиксированным объёмом, таймаутами и проверкой суммы; сумма не защищает от злоумышленника. Устройство предназначено для доверенного физического стенда, без UART-to-network bridge. Записи и дампы flash исключены: дамп может содержать старые секреты устройства.

## Что проверялось

- Список файлов для первого коммита и правила gitignore, включая вложенный сторонний Git clone.
- Шаблоны приватных ключей, токенов, email, телефонов, аппаратных адресов, домашних IP и пользовательских путей в публикуемых файлах.
- Ручной просмотр Python-утилит, C-приложений/адаптера I2C и PowerShell-сборок: явных сетевых обработчиков, eval/exec и запуска shell из недоверенных входов нет; UART-upload ограничен 96 000 байт, I2C-write — 256 байт.
- Лицензионные заголовки vendored ST API сохранены; полная безопасность стороннего C-кода не доказана.

Сборка и аппаратные испытания описаны в журнале как исторические результаты. Во время подготовки публикации устройства не прошивались, голос не записывался, серверные настройки не изменялись. Двигатели и безопасная остановка ещё не реализованы; VALID от дальномера сам по себе не разрешает движение.

## Правила Git

Публикуем исходники, sdkconfig.defaults, platformio.ini, документацию, исторические цены и лицензии стороннего кода. Не публикуем реальные .env, ключи, cookies, IDE/MCP-настройки, личный рабочий контекст, сырые сессии покупок, аудио, flash-dumps, логи и сборки. `.env.example` допустим только с фиктивными значениями. gitignore не удаляет уже закоммиченные секреты: при обнаружении нужна ротация и отдельная очистка истории.

При сообщении об уязвимости не прикладывайте реальные ключи, адреса доставки, дампы памяти или записи голоса в публичный issue.

Серверная часть полностью исключена из публичного набора после автоматической проверки публикации; описания топологии и доступа не публикуются.
